# ADR-0029: 검증은 층으로 쌓고, 커버리지는 목표가 아니라 래칫이다

- 상태: Accepted
- 날짜: 2026-07-30

## 맥락

이 저장소의 전제는 "기계가 검증한다"이다(ADR-0010). 그 전제 위에 게이트 8종이 서 있는데,
`AGENTS.md` 의 지뢰 목록은 같은 문장을 네 번 반복한다 — **"게이트가 전부 초록인데 이건 안
잡힌다."** 실제로 그렇게 새어 나간 것들:

| 새어 나간 것                    | 어디서 터졌나      | 왜 게이트가 못 봤나                                |
| ------------------------------- | ------------------ | -------------------------------------------------- |
| Node 미들웨어 거부              | 배포               | `next build` 는 통과, 배포 번들러만 거부           |
| og:image CPU 한도(Error 1102)   | **프로덕션**       | 빌드는 성립, **런타임 정책**이 다르다              |
| 마이그레이션 0007 트랜잭션 결함 | 적대적 리뷰가 잡음 | 스크래치 sqlite 는 자동커밋이라 pragma 가 먹었다   |
| 캐시 키 정규화·조건부 요청 누출 | 적대적 리뷰가 잡음 | `caches` 가 `next dev` 에 없어 e2e 가 통째로 못 봄 |

1행은 CI 에 `opennextjs-cloudflare build` 를 넣어 이미 닫혀 있었고, 3행은 `migration-0007.spec.ts`
가 트랜잭션 안에서 재생해 닫았다. **2행과 4행은 이 ADR 을 쓰는 시점까지 열려 있었고, 2행은
프로덕션 인시던트로 실현됐다** — 아래 층 5(배포 후 스모크)와 층 1(워커 풀에서 캐시 분기 직접
테스트)이 각각 그 둘을 닫는다.

여기에 오늘(2026-07-30) 잰 사실이 하나 더 붙는다. **커버리지를 한 번도 측정한 적이 없다.**
처음 재니 68.3% 였고, 그런데 `coverage.all` 없이 재면 **86.5% 로 보인다** — 테스트가 한 번도
import 하지 않은 파일은 istanbul 리포트에 아예 안 실리기 때문이다. 그렇게 빠진 26개 파일에
`app/api/auth/callback/chzzk/route.ts`(42 stmt)가 있었다. 그 파일은 **유닛도 e2e 도 안 봤다** —
e2e 로그인은 치지직 OAuth 를 안 태우고 access 쿠키를 직접 서명하므로(ADR-0021) 콜백 경로를
지나가지 않는다. 즉 이 저장소에서 가장 보안에 민감한 코드 중 하나에 검증이 0 이었는데, 그 사실이
**측정을 안 했기 때문에 안 보였고, 측정을 잘못했으면 여전히 안 보였을 것이다.**

같은 자리가 넷 더 있었다. 요청이 바깥에서 처음 닿는 코드 — API 라우트 5개(164 stmt)와
`middleware.ts`(32 stmt) — 가 전부 0% 였다. 라우터 프로시저는 caller 단위 테스트가 촘촘히 보지만
**caller 는 HTTP 를 안 타므로 그 앞에 선 CSRF 가드(Sec-Fetch-Site·Origin)를 지나가지 않는다.**
가드를 통째로 지워도 게이트 8종이 전부 초록이었다는 뜻이다.

## 결정

**검증을 다섯 층으로 명시하고, 각 층이 무엇을 보고 무엇을 못 보는지 못박는다. 커버리지 게이트는
목표치가 아니라 래칫(바닥)으로 건다.**

### 층

| #   | 층                        | 도구                               | 보는 것                                              | **구조적으로 못 보는 것**                   | 상태 |
| --- | ------------------------- | ---------------------------------- | ---------------------------------------------------- | ------------------------------------------- | ---- |
| 1   | 유닛 · workerd            | Vitest + pool-workers (ADR-0008)   | 순수 도메인·머신·서버 계약·D1 쿼리                   | DOM, 파일시스템(`fs` 없음), 실제 HTTP 왕복  | 있다 |
| 2   | 유닛 · dom                | Vitest + happy-dom (ADR-0008 확장) | 컴포넌트 배선·머신↔DOM 이벤트                        | 서버 계약(tRPC 를 목으로 교체), 레이아웃·색 | 있다 |
| 3   | e2e · `next dev`          | Playwright `--project=smoke`       | 3페이지 동작 패리티, 규칙 강제(`routes`·`copy-tone`) | **`caches` 등 workerd 전역** — dev 에 없다  | 있다 |
| 4   | 배포 번들 · workerd       | `wrangler dev` + 스모크 스크립트   | **번들이 부팅해 페이지를 서빙하는가**                | 실제 CPU 한도, 엣지 캐시, 프로덕션 시크릿   | 있다 |
| 5   | 배포 후 · 프로덕션 스모크 | Deploy 워크플로의 같은 스크립트    | **요청당 CPU 10ms**, DNS·시크릿 주입·라우트 실동작   | 되돌리지는 않는다 — 사람이 판단한다         | 있다 |

여기에 축을 가로지르는 둘:

- **접근성** — `axe-core` 자동 스캔이 층 3 에 붙는다(`e2e/a11y.spec.ts`, 4페이지 × 2폭). 대비
  4.5:1·ARIA·라벨·랜드마크를 손 열거가 아니라 기계가 센다. 규칙은 WCAG 2.1 AA 로 좁힌다 —
  axe 기본값의 `best-practice` 를 섞으면 "기준 위반"과 "취향"이 한 실패로 보여 판단이 흐려진다.
- **시각 회귀** — 층 3 의 `--project=visual`. 베이스라인이 OS 별 파일이라 **CI 에 없다**(의도).
  로컬 dev 회귀 + 사람의 육안 패리티 판단용.

### 층 4 는 계획과 다르게 지어졌다

처음 표는 층 4 를 "Playwright 스펙을 preview 위에서 한 번 더 돌려 **`caches` 등 workerd 전역
계약**을 본다"로 적었다. 실제로 지을 때 그 근거가 사라져 있었다 — **그 계약을 층 1 이 이미
보고 있었다.** 워커 풀 테스트는 진짜 workerd 라 `caches.default` 가 있고, `api/fanart/[key]` 의
캐시 키 정규화·캐시 히트 시 조건부 요청이 거기서 뮤테이션 검증까지 끝났다. 같은 스펙을 두 번
돌리는 비용만 남았을 것이다.

그래서 층 4 를 **"배포 번들이 실제로 부팅해 페이지를 서빙하는가"** 로 다시 정의했다. 이건 아직
아무도 안 보고 있었다 — CI 의 `opennextjs-cloudflare build` 는 **번들이 만들어지는 것**까지만
보고, 그 번들이 workerd 에서 뜨는지는 배포하고 나서야 알 수 있었다. 층 5 가 같은 것을 더 강하게
보지만 **층 5 는 배포 후**다. 층 4 는 프로덕션에 나가기 전 마지막 기회다.

구현은 층 5 와 **같은 스크립트**(`scripts/post-deploy-smoke.mjs`)에 origin 만 바꿔 넘긴다 —
"서빙되는가"의 판정이 배포 전후로 갈리면 층 4 를 통과하고 층 5 에서 죽는 이유를 사람이 다시
추론해야 한다.

층이 겹치는 건 낭비가 아니라 설계다. 아래 칸("못 보는 것")이 위 층을 부르는 이유이고, 새 검증을
어디 둘지 묻는 질문의 답은 **"어느 층이 이걸 구조적으로 볼 수 있나"** 다.

### 커버리지

- `vitest.config.ts` 에서 **항상 켜진다**(`enabled: true`) — 별도 스크립트로 빼면 로컬과 CI 가
  갈려 "로컬에서 게이트를 그대로 돌린다"가 깨진다. 8.6s → 10.5s 다(실측).
- **provider 는 `istanbul`** — 기본값 v8 은 `node:inspector` Session 을 쓰는데 workerd 엔 없다
  (워커 풀 스펙 35개가 `ERR_METHOD_NOT_IMPLEMENTED` 로 죽는다, 실측).
- **`all: true`** — 안 켜면 "안 덮인 파일"이 리포트에서 통째로 빠져 도구가 자기 목적을 배반한다.
- **임계치는 래칫이다.** 현재 수치 바로 아래에 박고, 테스트를 늘릴 때마다 같이 올린다.
- **집계 임계치 위에 신뢰 경계 경로별 임계치를 얹는다.** 저장소 전체 한 숫자면 인증 코드가 0% 로
  들어와도 다른 곳이 늘어 통과한다(적대적 리뷰 지적). 신뢰 경계는 **요청이 바깥에서 처음 닿는
  자리** 셋이다: `src/features/auth/**` · `src/app/api/**` · `src/middleware.ts`. 셋 다 잠겼다.

  | 경로                   | 처음 잰 값 | 지금  |
  | ---------------------- | ---------- | ----- |
  | `src/app/api/**`       | **0%**     | 97.6% |
  | `src/middleware.ts`    | **0%**     | 96.9% |
  | `src/features/auth/**` | 95.3%      | 95.4% |

  값은 실측 바로 아래에 **소수점 한 자리까지** 박는다. 정수로 내리면 95.34 에 95 를 박는 셈이라
  0.34%p 만큼 후퇴가 통과하는데, 신뢰 경계에서 그건 "작은 미검증 분기 하나"가 통째로 들어올 수
  있다는 뜻이다(코드 리뷰 지적). 그리고 **100% 인 축은 100 으로 박는다** — 이 셋에 한해서는 새
  코드 한 줄이 안 덮이면 즉시 빨개지는 게 맞다. 그게 부담이면 낮출 것은 임계치가 아니라 그 코드를
  신뢰 경계에 두는 선택이다.

  **0% 인 경로에는 임계치를 안 건다**(0 은 어떤 후퇴도 못 막고 "잠갔다"는 착시만 만든다) —
  그 경로를 덮는 PR 이 테스트와 임계치를 **같이** 넣는다.

## 근거

- **"게이트가 초록인데 안 잡힌다"의 답은 게이트를 조이는 게 아니라 층을 하나 더 얹는 것이다.**
  Error 1102 는 어떤 로컬 게이트로도 못 잡는다 — 빌드는 성립하고 런타임 정책만 다르기 때문이다.
  그 층은 프로덕션에 실제 요청을 보내는 것뿐이고, 그래서 5층이 있어야 한다.
- **커버리지 숫자가 낮은 자리가 곧 위험은 아니다 — 그래서 층 표가 먼저 온다.** `src/app` 이
  48.9% 인 건 page/layout/컴포넌트를 층 3 이 실제로 렌더해서 보기 때문이다. 위험한 건 낮은
  수치가 아니라 **어느 층에도 안 걸린 코드**이고, 그건 층 표와 커버리지를 겹쳐 봐야 보인다.
  OAuth 콜백이 정확히 그 교집합이었다.
- **래칫이 목표치보다 맞는 이유는 이 저장소가 테스트에서 얻는 것이 커버리지가 아니라 회귀
  차단이기 때문이다.** 80% 를 미리 박으면 숫자를 채우려는 테스트가 섞여 들어오는데, 이 저장소의
  테스트는 대부분 "실제로 터진 것"을 못박은 것들이다(`migration-0007.spec.ts` 가 그 전형).
  래칫은 그 문화를 안 흔들면서 후퇴만 막는다.
- **자동 롤백을 안 하는 이유.** D1 마이그레이션은 안 되돌아간다. 워커만 되돌리면 `deploy.yml`
  주석이 이미 경계하는 "구 워커 + 새 스키마" 스큐가 되고, 그건 지금 상태보다 나쁠 수 있다.
  스모크 실패는 사람을 부르는 신호로 충분하다.

## 기각한 대안

- **커버리지 v8 provider** — workerd 에서 못 돈다(실측). 선택지가 아니었다.
- **목표치 80% 를 지금 박는다** — 위 근거. 대신 래칫을 올리는 것이 각 PR 의 일부가 된다.
- **레이어 전체에 임계치(core 90 / app 60 / db 70 …)** — 예외를 늘리기 쉽고, 무엇보다 **낮은
  수치의 원인이 "층 3 이 본다"라면 그건 임계치가 아니라 층 표로 표현할 것**이다. 채택한 경로별
  임계치는 이것과 목적이 다르다 — 커버리지를 층별로 **관리**하려는 게 아니라, 집계가 **가려서는
  안 되는 자리**를 못박는 것이다. 그래서 대상이 레이어가 아니라 신뢰 경계 셋뿐이다.
- **커버리지를 `npm run test:coverage` 로 분리** — 로컬 `npm test` 와 CI 판정이 갈린다.
- **dev e2e 를 preview e2e 로 교체** — dev 전용 배선(e2e 세션 키 주입, ADR-0021)을 다시 짜야
  하고 실패 시 디버깅이 어려워진다. 층 3 과 4 는 보는 게 다르므로 둘 다 둔다.
- **층 4 에서 Playwright 스펙 전체를 다시 돌린다** — 처음 계획이 이거였는데, 그 근거였던
  "`caches` 등 workerd 전역 계약"을 층 1 이 이미 보고 있어 같은 스펙을 두 번 돌리는 비용만
  남았다(위 「층 4 는 계획과 다르게 지어졌다」). 스모크로 좁혀 CI 를 +15초 안에 뒀다.
- **스모크 실패 시 자동 롤백** — 위 근거(D1 스큐).
- **스모크 실패를 경고로만 남긴다** — 사람이 로그를 봐야 알게 되므로 루프가 안 닫힌다.
- **접근성 기존 위반을 baseline 으로 봉인** — 봉인된 위반이 영영 남는다. 나오면 고친다.

## 결과

- (+) 검증을 새로 짤 때 "어디에 둘 것인가"가 표 하나로 답이 된다.
- (+) OAuth 콜백처럼 **어느 층에도 안 걸린 코드**가 커버리지 리포트로 드러난다.
- (+) 프로덕션 인시던트를 배포 워크플로가 즉시 빨갛게 만든다 — Error 1102 를 발견한 건 게이트가
  아니라 사용자였다.
- (+) 접근성 위반이 손 열거 목록 밖에서도 잡힌다. 검출력은 위반 셋(`image-alt`·`button-name`·
  `color-contrast`)을 실제로 심어 확인했다 — 셋 다 잡혔다.
- (−) 층 5 는 **프로덕션에 요청을 보낸다** — 읽기 전용이지만 배포마다 트래픽이 는다(6개 × 2회).
- (−) 층 4·5 가 같은 스크립트를 쓰므로 그 스크립트의 결함은 두 층에 동시에 생긴다. 대신 판정이
  갈리지 않는다 — 그 교환을 알고 골랐다.
- (−) axe 는 **기계가 셀 수 있는 것만** 센다. 초점 순서가 말이 되는지, 라벨 문구가 뜻이 통하는지는
  여전히 사람 몫이다 — 초록이 "접근성 OK"라는 뜻은 아니다.
- (−) 래칫은 사람이 올려야 한다. 안 올리면 바닥이 낡아 새 코드가 안 덮여도 통과한다 —
  그래서 커버리지를 올리는 PR 은 임계치도 같이 올린다(규칙은 AGENTS.md).
