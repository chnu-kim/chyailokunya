# 쿠냐 디자인

이 사이트에는 이미 내린 시각 결정이 많다. 요청을 받으면 먼저 그 결정들과 충돌하는지 확인한다.
충돌하면 만들기 전에 말한다. 아키텍처·배포 규칙은 `AGENTS.md`, 결정의 이유는 `docs/adr/` 에 있다.

## 착수 전

다음 중 모호한 것이 있으면 한 번에 묶어서 묻는다. 모호하지 않으면 묻지 않는다. 받은 답은 사용자가
뒤집기 전까지 이 세션의 제약으로 유지한다.

- 어느 페이지·섹션인가. `/`·`/landing`·`/games`·`/schedule` 이고, index 와 landing 의 분리는
  결정 사항이다(ADR-0011).
- 새 부품인가, 기존 부품의 변형인가. 기본은 변형이다.
- 라이트·다크 양쪽인가. 사진지 섬(`.polaroid`) 안인가, 밖인가.
- 좁은 화면에서 어떻게 되는가. 세 가지를 함께 답한다. 어느 브레이크포인트를 쓰는지(새 값을
  만들지 말고 `src/app` 의 기존 `@media` 폭에서 고른다. 공유값은 560 뿐이다), 넓은 배치가 무엇으로 줄어드는지
  (열 수·`order`·사라지는 것), 무엇을 접거나 감추는지. 감추는 것은 우연이 아니라 결정이어야
  한다. `@container` 는 저장소에 아직 없으니, 처음 들이려면 먼저 묻는다.

## 토큰

색·타입의 정본은 `src/app/globals.css` 하나다. 생 hex 는 그 파일의 `:root`/`[data-theme="dark"]`
안에만 둔다(ADR-0005).

- 새 유틸리티는 토큰 유틸리티(`bg-surface`, `text-fg-muted`)로 쓴다. 이식한 크롬·페이지 CSS 는
  `var(--token)` 으로 읽는다. 그 CSS 를 유틸리티로 다시 쓰지 않는다. 손으로 튜닝한 값과 근거
  주석이 촘촘하고, unlayered 라 유틸리티를 이기도록 설계돼 있다.
- 테마에 따라 바뀌는 색은 `@theme inline` 에 둔다. 일반 `@theme` 에 두면 값이 굳어 `data-theme`
  전환이 조용히 죽는다. 정적 스케일(타입·간격·라운드·그림자·이징)만 일반 `@theme` 에 둔다.
- 새 색이 필요해 보이면 기존 토큰 조합부터 의심한다. 그래도 더하게 되면 라이트·다크 값을 함께
  넣는다.

## 부품은 있는 것을 쓴다

새로 그리기 전에 `chrome.css` 를 찾는다.

| 필요한 것 | 부품                                                                 |
| --------- | -------------------------------------------------------------------- |
| 사진      | `.polaroid` (+ `figcaption`, `.clip`)                                |
| 카드·표면 | `.paper` (`--surface` + `--border` + `--shadow-card`)                |
| 버튼      | `.btn` / `.btn--primary` / `.btn--secondary` / `.btn--accent`        |
| 상태·라벨 | `.chip` / `.chip--ink` / `.chip--ok` / `.chip--warn` / `.chip--live` |
| 붙임 장식 | `.tape` / `.clip`                                                    |
| 모달·시트 | 네이티브 `dialog` + `showModal()`                                    |

- "아직 없다"는 상태는 games 의 빗금 + 사진지 톤 플레이스홀더(`--thumb-paper`·`--thumb-mark`·
  `--thumb-edge`) 하나로 표현한다.
- 영어 eyebrow 라벨은 붙이지 않는다. 템플릿 티가 나서 이미 걷어 낸 것이다.
- 모달은 네이티브 `dialog` 로 만든다. 포커스 트랩·Esc·inert·포커스 복원을 브라우저가 맡는다.
  모달이 열려 있으면 바깥이 inert 라 라이브 영역이 읽히지 않는다. 결과 피드백은 모달 안에서 한다.

## 접근성은 계산으로

- 대비는 본문 4.5:1, 24px 초과 텍스트와 UI 컴포넌트 3:1 이다. 스크립트로 계산하고, 요소가 실제로
  앉는 배경을 전부 넣는다. 글자를 24px 아래로 줄이면 기준이 3:1 에서 4.5:1 로 바뀐다. 그래서
  크기와 색은 한 쌍으로 다룬다. `.polaroid figcaption` 의 `--brand-taupe` 는 큰 텍스트 기준으로만
  통과한다(`--text-xl` 25px).
- 터치 타깃은 44×44 다. 높이만 보지 말고 폭도 잰다. `min-height` 만 준 요소의 폭은 형제가 남긴
  잔여값이라 상태가 바뀌면 조용히 미달한다. `.btn`·`.field` 에는 기본 `min-height` 가 없다.
  좁은 폭에서 패딩을 줄였다면 글자 높이와 패딩의 합을 주석에 남긴다(`chrome.css` 의 `.nav__link`).
- 포커스 링은 `--focus` 를 쓴다(`--accent` 는 채움용). 장식은 `aria-hidden="true"` 를 단다. 새 창
  링크에는 sr-only `(새 창에서 열림)` 을 붙인다. 애니메이션은 `prefers-reduced-motion` 가드 안에
  넣는다.
- 인터랙티브 요소에 비인터랙티브 role(`listitem` 등)을 주지 않는다. 목록형 링크는 ul/li 로 감싼다.

**사진지 섬.** 폴라로이드와 게임 카드는 두 테마 모두 크림색으로 남고, 다크에서는 라이트 토큰
일부를 다시 선언한다. 섬 안에 부품을 넣기 전에 그 토큰이 되돌림 목록에 있는지 확인한다.
예를 들어 다크의 `--border-strong` 은 크림 위에서 1.01:1 로 사라진다. 입력 컨트롤은 섬 안에 두지
않고 `.paper` 위에 둔다.

## 장식과 레이아웃

- 장식 모티프는 화면 단위로 센다. 결정적인 장식은 화면당 하나로 하고, 하나를 더하려면 하나를
  먼저 뺀다.
- 장식은 인라인 SVG 로 만든다. 이모지 아이콘은 쓰지 않는다. 손그림은 SVG 로 따라 그리지 않고,
  테마별 PNG 두 장(라이트 잉크 / 다크 초크)을 `background-image` 로 바꿔 끼운다. 이미지는 사용자가
  준다. 생성하지 말고 필요한 목록을 요청한다.
- 객관적인 실패 조건은 다음과 같다. 겹침, 상자 밖으로 나간 문자열, 어느 폭에서든 생기는 가로
  스크롤, 이웃을 밀어내는 `nowrap`.
- 고정 px 트랙에는 반드시 해제 폭을 붙인다(`.hero__grid` 360, `.profile__grid` 320 → 860 에서
  1열). 감축 경로의 끝이 1열이 아니어도 된다(`.games` 는 2열에서 멈춘다). 다만 그 선택과 근거를
  주석에 적는다.
- 좁은 화면에서는 카드 회전(`--rest-rot`)을 푼다(600). 560 이하의 폼은 바텀 시트로 띄운다.
- 좁은 화면은 판단하기 전에 390×800·320×800 에서 실측한다.

## 끝내기 전

실패한 항목은 묻지 말고 그 자리에서 고친다.

1. 게이트: `npm run typecheck && npm run lint && npm run format:check && npm run build`.
2. 시각 변경이면 `PORT=3100 npm run e2e:visual` 을 돌린다. 베이스라인을 갱신하기 전에 diff 를 눈으로
   본다. 갱신은 회귀를 지우는 행위이고, 전체를 재생성하므로 갱신 뒤 `git status` 로 의도한 파일만
   바뀌었는지 확인한다.
3. 좁은 폭: `e2e/narrow-body.spec.ts`·`nav-touch-target.spec.ts` 를 돌린다. 본문에 조작을 더했으면
   그 스펙의 터치 타깃 목록에도 적는다(손으로 열거한다). 스펙이 안 보는 새 clamp·`nowrap`·섹션은
   Playwright 로 직접 잰다. 덮임은 `click()`, 크기는 `boundingBox()` 로 본다.
4. 이번에 건드린 색·크기 조합의 대비를 라이트·다크 양쪽에서 다시 계산한다.
5. 주석의 실측 수치는 근거가 된 값을 바꿀 때 함께 고친다. 다시 계산할 수 없는 수치는 적지 않는다.
   주석에 셀렉터·태그 리터럴을 인용하지 않는다.
6. 새 `@media` 폭을 만들었으면 왜 기존 값으로 안 되는지 주석에 적는다.
7. 사용자가 가리킬 요소에 `data-od-id` 를 붙였는지 확인한다.
8. 장식 모티프 개수가 늘지 않았는지 확인한다.

보고는 바꾼 파일, 결과, 남은 항목 세 줄로 한다. 하지 않은 일은 했다고 보고하지 않는다.

## 안 내보내는 것

보라색 그라디언트 워시, 배경마다 그라디언트, 이모지 아이콘, 왼쪽 컬러 보더 액센트 카드,
제목마다 아이콘, 디스플레이 페이스로 쓴 Inter/Roboto/Arial, 지어낸 수치와 필러 카피, 사이트에
없는 빈 상태 언어, 데모용 컨트롤. 값이 없으면 정직한 플레이스홀더를 쓴다. 넣으면 좋을 것 같은
콘텐츠가 떠오르면 넣지 말고 먼저 묻는다.

문구는 `AGENTS.md` 의 코드 컨벤션을 따른다. 사용자에게 보이는 문구는 합쇼체이고, 값 칸은
표기로 쓴다. 문구에는 사실만 쓰고 꾸밈말·고양이 말투·이모티콘을 지어 넣지 않는다.
